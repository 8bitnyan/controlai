## ADDED Requirements

### Requirement: Single Traefik v3 instance as the only host-bound entrypoint

controlai SHALL provision exactly one Traefik v3 container on the host
bound to `:80`, `:443` (HTTPS), and `:8883` (MQTT/TLS). Tenant-owned
broker, ingest, and TSDB containers SHALL NEVER expose host ports.

#### Scenario: No host-port conflicts when adding sites
- **WHEN** 10 sites are created across multiple tenants
- **THEN** `docker ps --format '{{.Ports}}'` SHALL show host bindings only on the Traefik container; no broker, ingest, or TSDB container SHALL appear with `0.0.0.0:` bindings

### Requirement: MQTT routing by SNI passthrough

Traefik SHALL be configured with a TCP entrypoint at `:8883` and TCP
routers per site keyed on `HostSNI(...)` with `tls.passthrough=true`,
forwarding the TLS handshake unmodified to the upstream broker. mTLS
termination SHALL happen at the broker, so client certificates SHALL
reach the broker for CN-based authentication.

#### Scenario: MQTT client reaches the right broker
- **WHEN** a gateway connects to `<host>:8883` with `ServerName=ste_seoul.tnt_acme-corp.controlai.local`
- **THEN** Traefik SHALL route the TCP stream to the `ste_seoul` broker container of `tnt_acme-corp` and the broker SHALL see the gateway's client certificate intact for mTLS auth

#### Scenario: Unknown SNI rejected
- **WHEN** a gateway connects with an SNI not registered in any dynamic route
- **THEN** Traefik SHALL reject the connection cleanly without crashing other routes

### Requirement: HTTP routing by domain for the daemon API

Traefik SHALL expose the controlai daemon's REST API on
`api.controlai.<base-domain>` over HTTPS, terminating TLS at Traefik and
forwarding cleartext to the daemon's TCP listener.

#### Scenario: REST API reachable over HTTPS
- **WHEN** an authenticated client calls `https://api.controlai.<base-domain>/v1/health` with a valid bearer token
- **THEN** the daemon SHALL respond with HTTP 200 and a JSON health payload

### Requirement: Dynamic configuration written atomically

controlai SHALL drive Traefik's file provider with `watch: true` rooted
at `/var/lib/controlai/shared/traefik/dynamic/`. The daemon SHALL write
each dynamic config file by writing to a temporary path in the same
directory and atomically renaming over the destination so fsnotify
events fire reliably.

#### Scenario: New site route appears within 5 seconds
- **WHEN** a new site is created
- **THEN** controlai SHALL write the dynamic-config YAML and Traefik SHALL pick up the new TCP and HTTPS routers within 5 s of the rename event

#### Scenario: Concurrent edits never produce truncated files
- **WHEN** two `controlai site` modifications occur in rapid succession that both rewrite the same dynamic-config file
- **THEN** Traefik SHALL NEVER observe a truncated or partially-written file thanks to the atomic-rename pattern

### Requirement: Optional Let's Encrypt cert resolver

controlai SHALL support an opt-in `shared.traefik.acme=true` setting that
configures a Traefik `certResolvers` entry for Let's Encrypt with HTTP-01
challenge over the `:80` entrypoint. When disabled, controlai SHALL use
the self-signed certificates rendered by the PKI module.

#### Scenario: ACME disabled in MVP defaults
- **WHEN** controlai is initialized without explicit configuration
- **THEN** ACME SHALL be off and Traefik SHALL use the self-signed server certificate generated by controlai's PKI module
