## Requirements
### Requirement: Static RSS profile table per component combination

controlai SHALL maintain a static lookup table that returns predicted
RSS in MB for the host overhead and for each combination of
`(broker.kind, throughput.tier, ingest.direction)` plus a per-tenant
TSDB cost. The table SHALL be regenerated by a benchmark script and
checked into source, and SHALL be the sole input to capacity prediction.

#### Scenario: Profile table contains all valid permutations
- **WHEN** controlai is built
- **THEN** every combination of broker.kind ∈ {mosquitto, emqx}, throughput.tier ∈ {low, mid}, ingest.direction ∈ {uni, bi} that the broker matrix allows SHALL have an entry in the table

### Requirement: Admission control rejects overcommit

Every `POST /v1/tenants` and `POST /v1/tenants/{tid}/sites` SHALL pass
through admission control that computes the projected total RSS after
the requested addition and rejects with HTTP 409 if the projection
exceeds 85 % of `(/proc/meminfo.MemTotal − host_overhead)`.

#### Scenario: Sixth tenant on t3.medium rejected
- **WHEN** the host reports MemTotal=4 GiB and 5 mosquitto-low-uni tenants already exist
- **THEN** `POST /v1/tenants` for a sixth tenant SHALL be rejected with HTTP 409 and the response body SHALL include the projected total and the headroom limit

#### Scenario: Adding a site rejected if it pushes over the limit
- **WHEN** adding an EMQX-mid-bi site to an existing tenant would push the projection over 85 %
- **THEN** the request SHALL be rejected with HTTP 409 and the response SHALL identify the limiting resource

### Requirement: What-if capacity query

controlai SHALL expose `GET /v1/capacity[?plan=...]` and the CLI
`controlai capacity [--plan tenant=...,site=...]` that returns current
projected RSS, headroom, and per-tenant breakdown plus, when `plan` is
provided, the additional RSS the plan would consume and a boolean
`admissible`.

#### Scenario: What-if returns admissible:true under the limit
- **WHEN** a what-if plan for one additional mosquitto-low-uni site would land at 70 % of usable
- **THEN** the response SHALL include `admissible: true` and the predicted total

#### Scenario: What-if returns admissible:false at the limit
- **WHEN** the planned addition would land at 90 % of usable
- **THEN** the response SHALL include `admissible: false`, the projected total, and a `reason` string

### Requirement: Tier rejection by host class

controlai SHALL reject `throughput.tier=high` site requests on hosts
whose detected instance class is t3.medium or smaller, returning HTTP
400 with a message recommending an upgrade to t3.large or larger.

#### Scenario: High tier refused on t3.medium
- **WHEN** an operator submits a site with `throughput=high` on a host whose `/proc/meminfo.MemTotal ≤ 4 GiB`
- **THEN** the request SHALL be rejected with HTTP 400 stating "high tier requires t3.large or larger"
